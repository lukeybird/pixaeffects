MAC CERTIFICATE / NOTARIZATION

The existing Developer ID Application private key must stay in the user's local Keychain. No .p12 export, credentials pasted into chat, passwords in shell arguments, secrets committed to Git, or private keys uploaded to GitHub/Vercel. The public certificate is embedded through code signing; customers do not install the developer's private key or Keychain profile.
Check locally that Xcode command-line tools, xcrun notarytool and the signing identity are available. Use an existing local notarytool Keychain profile (the helper defaults to PixaShop-Notary); do not recreate a paid membership. If a password/Keychain prompt occurs, let the user answer it locally.

For the fourteen NEW suite editors, release-tools/macos_candidate.py signs a COPY, validates bundle ID/version and requested architecture, signs nested code inside out with hardened runtime/secure timestamp, submits the app to Apple, staples/validates it, runs Gatekeeper assessment, creates a drag-to-Applications DMG with license notices, signs/notarizes/staples that DMG and writes a hash/submission report. It never publishes. Its four pure bundle-validation tests passed; the full Mac flow still must be executed/reviewed locally.

Example AFTER a real Mac release build and package stage exist:
  python3 release-tools/macos_candidate.py pixavector /absolute/path/to/PixaVector.app --architecture arm64 --identity "Developer ID Application: exact local signing identity" --profile PixaShop-Notary --output /absolute/path/to/a/fresh/candidate-output
Use x86_64 on an Intel-only build. Use universal ONLY for a real combined arm64+x86_64 executable; the helper checks lipo output and refuses mislabeled architecture. Do not call the default host-only build universal. By default, license notices come from the Licenses folder beside the app in package.py's stage; --notices can name the matching folder explicitly. Retain all license/attribution material. Finish the desired Finder icon/arrow presentation before the public DMG is frozen.

The resulting file is a NOTARIZED TEST CANDIDATE, not automatically a finished release. Test a fresh downloaded/quarantined copy on the target architecture, verify codesign, stapler and spctl, install by dragging to Applications, activate, edit/save/reopen, and test updating. On Invalid/Rejected, fetch the Apple notary log for the submission ID using the local profile and fix the specific issue. Do not disable Gatekeeper or remove quarantine as a substitute for successful distribution testing. Use the existing product-specific release scripts for Shop/Effects after reviewing their latest source and artifacts.
